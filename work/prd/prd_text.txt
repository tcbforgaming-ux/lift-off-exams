1. Project Overview
1.1 Purpose
Lift Off Exams is a DECA exam preparation platform designed to help users practice for official
DECA examinations through quizzes, tests, and infinite-run study modes.
The platform will support seeded test generation using Test IDs, a centralized question
repository, question reporting, administrative question management, and user accounts.
The platform is designed to generate tests from a global question repository rather than storing
completed tests.

5. Test Generation
5.1 Test IDs
Every generated test shall receive a unique 12-character alphanumeric Test ID.
Example:
AB4F9D72K1PQ
Requirements:
● Uppercase letters and numbers
● Used as a deterministic seed
● Used to recreate the same question pool
● Tests themselves are not stored

--- PAGE 5 ---
5.2 Seed Logic
The Test ID shall determine:
● Question selection
● Original question ordering
The Test ID shall not determine:
● Timer settings
● Test mode
● Scoreboard settings
Entering a previous Test ID shall recreate the same question pool and original question order.
Users may choose to:
● Retake the original test exactly
● Generate a shorter test using the same seeded question pool
● Randomize question order while keeping the same seeded question pool
Randomizing question order shall not create a new Test ID.
5.3 Tag Filtering
Users may select one or more tags when generating a test.
Tag filtering shall use AND logic.
Example:
Selected Tags:
● Marketing
● Hard
Only questions containing BOTH tags shall be eligible.
If insufficient questions exist to generate the requested test length, the system shall notify the
user and offer:
● Generate a shorter test using all matching questions

--- PAGE 6 ---
● Modify selected tags
● Return to test creation

19.4 Blueprint Validation System

--- PAGE 29 ---
Purpose
The platform shall continuously validate all blueprint presets against the current question
repository.
The purpose of this system is to ensure that blueprint-generated tests can be created accurately
using available questions.
Validation Rules
For every blueprint, the system shall calculate:
● Required question count per topic
● Available question count per topic
● Repository coverage percentage
Example:
Marketing State Blueprint
Topic Required Available Status
Promotion 11 27 Valid
Pricing 4 12 Valid
Selling 7 5 Insufficient
Blueprint Status
Each blueprint shall display one of the following statuses:
Valid
All required topic counts can be satisfied.

--- PAGE 30 ---
Example:
Marketing State Blueprint
Status: Valid
Warning
The blueprint can be generated, but one or more topics are approaching minimum availability.
Example:
Marketing State Blueprint
Status: Warning
A warning threshold shall be configurable by administrators.
Invalid
One or more required topic counts cannot be satisfied.
Example:
Marketing State Blueprint
Status: Invalid
Invalid blueprints shall identify the missing topic areas.
Administrator Dashboard
Administrators shall have access to a Blueprint Validation page.
The page shall display:

--- PAGE 31 ---
● Blueprint Name
● Status
● Coverage Percentage
● Missing Topics
● Total Available Questions
● Total Required Questions

÷
Required Questions

100

2. Weak Area Questions

--- PAGE 69 ---

● Quizzes

● Weak Areas
● Unseen Questions within Weak Areas

--- PAGE 70 ---

● Previously seen questions may re-enter the generation pool.
● Repetition avoidance shall remain active.
● Unseen questions shall continue to receive higher priority when available.
● A user shall only see a repeat question if they have seen all other applicable
questions to the selected tags have been answered.

--- PAGE 71 ---

-Weak Area Prioritization (if enabled)
-Repetition Avoidance
-Question Selection

-Question Selection

content and gradually evolves into a personalized remediation tool.

56. Blueprint Generation Rules
56.1 Annual Updates
Blueprints shall be updated according to official DECA blueprint releases.
Updates shall generally occur annually.
56.2 Administrative Control
Blueprint updates may be performed by Administrators and Owners.
56.3 Difficulty Handling
Blueprint-generated exams shall not attempt to balance or moderate question difficulty.
Question selection shall prioritize blueprint compliance.
56.4 Blueprint-Based Distribution

--- PAGE 87 ---
Generated exams shall attempt to proportionally match blueprint category distributions.
56.5 Repetition Avoidance
Questions appearing in a user’s previous two tests shall be deprioritized during
generation whenever sufficient alternatives exist.

If a username or display name contains a banned term:

● The user will be notified that the name contains an inappropriate word or phrase
● The user will be forced to create a new name
